# Security Policy

## Supported versions

This project is in early-stage development. Security updates are handled as they are identified.

## Reporting a vulnerability

Please do not open a public issue for security vulnerabilities.

Instead, email the maintainer privately with:

- summary of the issue
- affected version or commit
- reproduction steps
- impact assessment
- suggested fix, if known

The project does not yet publish a security email address. Use the repository owner or the preferred private channel defined by the maintainers in the project settings.

## Response expectations

We aim to acknowledge and assess reports promptly. Because this is an early-stage project, the response window may vary.

## Security principles

- validate all inputs
- enforce capability boundaries
- avoid implicit trust between components
- keep execution permits explicit and auditable
- do not log secrets or tokens
